Spaces have been introduced to allow for multi-client capabilities and separation of projects. There are currently two types of spaces:

  • Root Space: A top level space that can contain other spaces, but itself cannot be moved below another space.
  • Space: A regular space that can be part of a Root Space or any other Space.
For Example, you could create a Root Space for every company and use regular Spaces to define projects.

Behavior

Spaces have the following characteristics, which will determine their behaviour:
  • Assigned Users / User Groups:  Allows defined users or groups to see and select a space and work in the specified space. What they can do inside the space depends on the other permissions granted to the users by it's Roles and Group assignments.
  • Assigned Admins / Admin Groups:  Allows a user to change the space, add subspaces, add users and groups Exception for Root Spaces: Can only be edited by users with permission 'Space: Admin All'. There is no other rights this assignment grants. Any other admin privileges inside the space have to be granted by roles or groups.
  • Is Enabled: Enables or disables a space. If a space is disabled, the space and anything in it will not show up in select dropdowns nor other places like autocomplete. Projects below it can still be enabled and will be visible if not explicitly disabled.
  • Is Global: If a root space is set to global, everything stored in it can be selected and used from any space. If a regular space is set to global, things inside of it can be used by any space on the same level or below that level in that hierarchy.
  • Is Enabled: If a space is set to disabled, it will not show up in the space selector and it's entities will not show up for selection. Disabling a space will not break functionality. If an entity was selected/used while the space was enabled, this entity will stay selected/used until someone changes it.
  • Position in the Hierarchy: The position in the hierarchy influences certain things:
    • Administration: Direction is top-down, admins can access and administrate any space that is below the one they are assigned admin for. They cannot access spaces higher in the hierarchy.
    • Entity Access: Direction is bottom-up, users can access entities(Credentials, Dashboards etc...) that are in spaces above the one they are assigned too, but not in spaces below. This is true even if the user is not an assigned user of a parent space. This allows to share entities with sub spaces, and to create sub spaces and move entities into them without breaking functionality.
