Spaces have been introduced to allow for multi-client capabilities and separation of projects. There are currently two types of spaces:

  • Root Space: A top level space that can contain other spaces, but itself cannot be moved below another space.
  • Space: A regular space that can be part of a Root Space or any other Space.

Behavior

Spaces have the following characteristics, which will determine their behaviour:
  • Selectable Users / Groups:  Only users and groups can be selected that are somehow part of the selected space. To be able to select any user at all, there must be at least one user or group assigned to the root space.
  • Assigned Users / User Groups:  Allows defined users or groups to see and select a space and work in the specified space. What they can do inside the space depends on the other permissions granted to the users by it's Roles and Group assignments.
  • Editors / Editor Groups:  Allows a user to change the space, add subspaces, add users and groups. Exception for Root Spaces: Can only be edited by users with permission 'Space: Admin All'. There is no other rights this assignment grants. Any other admin privileges inside the space have to be granted by roles or groups.
  • Is Enabled: Enables or disables a space. If a space is disabled, the space and anything in it will not show up in select dropdowns nor other places like autocomplete. Projects below it can still be enabled and will be visible if not explicitly disabled.
  • Is Global: If a root space is set to global, everything stored in it can be selected and used from any space. If a regular space is set to global, things inside of it can be used by any space on the same level or below that level in that hierarchy.
  • Is Enabled: If a space is set to disabled, it will not show up in the space selector and it's entities will not show up for selection. Disabling a space will not break functionality. If an entity was selected/used while the space was enabled, this entity will stay selected/used until someone changes it.
  • Position in the Hierarchy: The position in the hierarchy influences the access:
    • Editing Access:  Direction is top-down, editors can access any space that is below the one they are an editor for. They cannot edit spaces higher in the hierarchy.
    • Entity Access:  Direction is bottom-up, users can access entities(Credentials, Dashboards etc...) that are in spaces above the one they are assigned too, but not in spaces below. This is true even if the user is not an assigned user of a parent space. This allows to share entities with sub spaces, and to create sub spaces and move entities into them without breaking functionality.

Default Spaces

The following spaces are created by default:

  • [DEF] Default:  This is the default space, it contains everything that has existed before the Spaces Feature has been introduced. Users get access to this space automatically. If you don't want this behavior, you can remove the "User" role from the space.
  • [GLB] Global:  An example global space, superusers have access to this one by default. Everything in a global Root Space can be used in any other space.
  • [ALL] All:  A special space for admin purposes. It shows everything in every space so things can be found if they vanish in the depths of hierarchical complexity.

Structuring

Following some considerations about how to structure your spaces:

  • Default only: If you use the application within the same company, the simplest way is to keep everything in the default space.
  • Default with Teams: Another way is to use the Default space, and add sub-spaces to it for different teams. This gives you the possibility to still move spaces around in the same root space.
  • Companies and Projects If you server multiple companies, you could create a Root Space for every company and use Regular Spaces to define projects.

Selecting and Filtering

When a feature makes use of spaces, the Space Selector will be displayed in the navigation bar at the top right. With this you can select the space you are currently working in and see data for. The Space selector contains only spaces you have been assigned to. Next to the Space Selector is a filter symbol, when clicking on it, you can switch between two different modes:

  • Inclusive (gray icon):  Lists of different features will show what is contained in the selected space, plus everything from other spaces you can access and make use of.
  • Exclusive (yellow icon):  Shows only what is contained in the selected space.

Deletion of Spaces

Spaces cannot be deleted and only disabled, what hides a space from selection dropdowns. Reason for this is that someone can move, for example, Item A (e.g. a Query) from Space A to Space B, while item A could still have dependencies to Space A. If Space A would now be deleted, Item A would lose it's dependencies and would cease to work for not very obvious reasons.

Another reason are the the default spaces, which could not be restored of deleted. There is also the circumstance that for backward compatibility with older version, Roles have been made part of the Default Space. If someone would delete the default space, the Roles would be deleted too, what would block the access for every user.

Moving of Spaces

Following are the rules for moving spaces:

  • Root Space:  Root Spaces cannot be moved to other spaces as they have to stay root spaces.
  • Regular Spaces:  Regular spaces can be moved in the hierarchy within the same Root Space. This allows for a strict separation of access. Also they cannot be moved to other Root Spaces as this could cause a lot of confusion regarding dependencies.
